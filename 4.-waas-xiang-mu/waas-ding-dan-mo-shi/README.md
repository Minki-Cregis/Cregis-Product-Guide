# WaaS 订单模式

1. 什么是 WaaS 订单模式？\
   \
   WaaS 订单模式是基于 Cregis 自托管钱包所建立的收款解决方案。该模式继承了自托管的核心原则，确保每位商家的资金皆完全隔离。商家无需自行分配地址，即可将加密货币付款直接收款至自己的自托管钱包中。商家可享有简单流畅的收款体验，且 API 整合过程亦极为简便。\
   \
   产品专为线上营商的商家而设，例如电商平台、SaaS、游戏、外汇、数字内容等按订单计算的收款模式。希望以最少对接成本接受加密货币收款，并直接在自己的钱包收到款项及获取实时收款通知。<br>
2. 收款规则<br>
   1.  **支持的加密货币**： Cregis 支持 **23 种加密货币**收款（包括 USDT、USDC、ETH、BTC、SOL、TRX 及 BNB）。


   2.  **启用收款币种**： 在「收款及转账」设置中，您可启用想接受的加密货币，并为每个币种设定收款地址。


   3.  **以法币下单、以加密货币收款**： 您不必以加密货币为订单标价，可直接以法币设定订单金额（订单货币）。付款方付款时，Cregis 会按 CoinMarketCap 即时汇率，将订单金额换算为支付币种的金额。


   4.  **即时通知**： 当收到付款时，Cregis 会实时通知商家付款状态。商家可根据状态（如足额付款、部分付款、超额付款、逾时或已取消）做出相应决策。


3. 核心记录\
   \
   WaaS 订单模式会在付款流程中保存六种类型的记录。了解这些记录，有助您掌握每个订单的进度，并正确使用后台、API 与回调。<br>
   1.  **订单记录**：当您创建订单时建立，并保存您在 API 提交的所有资料，例如订单金额、订单货币、支付币种、有效时间及付款方资料等。


   2.  **支付单记录**：当付款方的付款，与某张订单收款逻辑匹配时建立，并将订单与付款方地址、收款地址、交易哈希等链上资料关联起来。


   3.  **退款单记录**：当已收的款项不符合所提交订单的要求时建立，让您可将款项退回给付款方


   4.  **批量转账单记录**：当订单满足转账规则时建立，记录将资金批量转账至您的自托管地址的发起时间及订单。


   5.  **转账单记录**：与批量转账记录同时建立。它会按相同的收款地址将订单分组，并记录从收款地址转账至您的自托管钱包地址的转账资料


   6.  **异常支付单记录**：当某笔付款触发 AML 规则时或付款后无法匹配至任何订单的收款逻辑时建立，让您可以选择继续转账或退回该笔付款。


4. 记录状态\
   \
   每种记录都会按已定义的状态推进。以下为订单、退款与异常支付的状态及其含义。<br>
   1. 订单状态<br>
      1.  **新订单**：订单已创建，尚未收到任何付款，及仍在有效时间内。


      2.  **需补款**：已收到付款，但尚未满足订单金额，因此需要付款方进行补款。若订单包含付款方电邮，系统会自动向付款方发送补款电邮；否则，您需要将回调中的付款地址发送给付款方以完成补款。补款金额亦可于回调或查询订单 API 中取得。


      3.  **已支付**：已收到付款，且金额在商户设定的容差范围内，但款项尚未转账至您的自托管钱包。


      4.  **已转账**：金额已转账至您的地址。订单流程到此结束。


      5. **已取消** - 订单需要退款或已触发 AML 规则，因此无法继续。订单流程到此结束；系统会视情况触发退款或异常支付流程。<br>
      6. **已超时**：订单已过期，不再接受付款。订单流程到此结束。<br>
   2. 退款状态<br>
      1.  **已生成**：退款已触发，尚未完成。


      2.  **退款中**：退款已发起，正在处理中。


      3.  **退款成功**：款项已退回至目的地地址


      4.  **退款失败**：退款失败，需人工介入。此情况为极少发生。


   3. 异常支付单状态<br>
      1.  **已生成**：异常支付已触发，尚未完成。


      2. **转账中**：异常支付已发起，正在处理中。<br>
      3. **转账成功**：款项已退回至目的地地址。<br>
      4.  **转账失败**：转账失败，需人工介入。此情况为极少发生。


5. 转账规则\
   \
   您收到的款项会按以下规则分批转账至您的自托管钱包。您可在「收款及转账」页面查看及调整转账设定。<br>
   1.  **常规转账**：当累计待转账金额达到或超过等值 50 USDT（测试阶段）／500 USDT（正式阶段） 时，系统每 10 分钟执行一次转账。


   2.  **最低门槛转账**：若累计待转账金额仍低于上述常规转账门槛，则会触发最低门槛转账，确保资金每 24 小时至少转账一次。为方便新加入的商户测试，低于常规转账门槛的首笔交易，会在 10 分钟内自动触发此最低门槛转账。


   3.  **转账金额**：所有尚未转账订单的累计金额。


   4.  **转账地址**：您可选择 Cregis 自托管钱包地址来接收资金。


6.  补款<br>

    当首次付款金额低于订单金额时，订单不会立即失败，而是进入补付流程及发送补款（additional\_payment\_required）回调，让付款人可以支付剩余款项。补付流程仅在同时满足以下所有条件时才会触发。<br>

    * 实收金额少于订单金额减去少付容差（默认为 0）。<br>
    * 该订单的首笔付款。



    * 支付币种为稳定币。<br>

    请注意，付款货币将与首次付款相同。补款金额计算方式为，订单金额减去已付款金额。补款必须在 7 天内完成；若超过此期限，订单将进入全额退款程序。\
    \
    付款方能以以下其一方式完成补款：<br>

    * 您可查阅回调，取得补款地址后并提供给付款方继续付款。<br>
    * 若付款方透过收银台支付，页面将自动跳转至补款页面。<br>
    *   若在 API 创建订单时提供付款方电邮，系统将自动发送补款电邮。付款方可经电邮中的连结进入付款页面完成付款。

        <br>
7.  退款\
    \
    当已收款项与订单要求不符时，系统会发起退款，将多付或全部款项退回给付款方。退款分为部分退款及全额退款两种。\
    \
    a. 部分退款（超额支付）\
    \
    当付款金额高于订单金额时，原订单金额将继续转账流程，而超出部分则会进入退款流程。在此情况下，系统亦会触发部分退款回调，让商家可以并行处理转账与退款。部分退款将于以下条件下触发：



    * 实际付款金额大于订单金额加上超额容许值（默认为 0）。<br>

    b. 全额退款<br>

    当收到无效付款时，将触发全额退款。在此情况下，系统会同时触发退款回调及订单回调（已取消），因此原始订单流程会自动取消。全额退款将于以下其一条件下触发：<br>

    * 实付金额少于订单金额减去少付容差（默认为 0），且支付币种为非稳定币。<br>
    * 补款未能在 7 天期限内完成。<br>
    * 补款（第二次付款）后，实付金额仍少于订单金额减去少付容差（默认为 0）。

    \
    两种退款方式均可透过以下任一方式完成：<br>

    * 商户可透过退款记录并发起退款。<br>
    * 若付款方透过收银台付款，页面将自动跳转至退款页面。<br>
    * 若透过 API 创建订单时提供了付款方电邮，系统将向付款方发送退款电邮。付款方可经电邮中的连结进入退款页面。<br>
    * 联络 Cregis 支援团队协助处理。<br>

    请注意，退款币种与首次付款相同。若退款尚未处理，付款人电邮中的退款连结有效期最长为 7 天；超过 7 天后，您需透过 Cregis 客户端处理退款或联系 Cregis 客服团队。<br>
8. 服务费

| 收费类型    | 收费模式     | 收费来源      |
| ------- | -------- | --------- |
| 订单服务费   | 百分比／最低收费 | 团队余额／转账金额 |
| 退款手续费   | 固定费用     | 转账金额      |
| 异常支付手续费 | 百分比／最低收费 | 转账金额      |
