# 团队协作

## **什么是团队协作**

团队协作是 Cregis 面向企业团队提供的交易管理与多人协同能力。企业可以通过审批、签名等机制，将交易发起、业务审批和交易签名进行分离，由不同角色共同完成交易处理，从而降低单人操作风险，建立更加规范、安全的资金管理流程。

例如，企业可以设置：员工发起交易 → 财务审批 → 负责人审批 → 签名人签名 → 交易广播上链

通过团队协作，企业可以根据自身的资金管理制度，将不同成员分配到不同的业务环节中，实现职责分离、多人复核和操作留痕。团队协作适用于以下场景：

* **大额交易审批**：大额转账需要经过负责人审批后才能执行。
* **多人共同管理资金**：交易需要多个成员参与确认或签名。
* **职责分离**：由业务人员发起交易，财务人员负责审批，签名人员负责签名。
* **交易风险控制**：发起的交易在满足特定条件时进入人工审批。
* **企业资金管理**：通过审批和签名机制建立标准化的资金操作流程。



## **协作工作流程**

Cregis 的团队协作主要围绕交易发起、策略匹配、审批、签名和广播上链几个环节展开。一笔交易的典型处理流程：发起交易 → 策略匹配 → 审批 → 签名 → 广播上链

1. **发起交易**

团队成员或业务系统可以根据自身权限发起交易。交易可以来自不同的业务入口，例如：

* 钱包/子地址
* WaaS API
* 应用市场

交易发起后，Cregis 会根据团队配置的策略判断是否需要进入审批流程。

2. **策略匹配**

系统会根据交易的相关条件匹配已启用的[策略](https://support.cregis.com/cregis-wallet-guide/zh-cn/risk_management/policy_engine)。例如：单笔转账金额 ≥ 100,000 USDT 时，需要经过审批。如果交易满足策略条件，则进入对应的审批流程，如果交易未触发策略，则直接进入签名流程。是否需要审批，由交易触发的策略决定。

3. **审批**

如果交易触发了策略，则按照策略配置的审批流程依次进行审批。例如：员工发起 → 财务审批 → 负责人审批审批人可以查看交易的详细信息，并选择：

* 审批
* 驳回

所有审批节点完成审批后，交易进入签名阶段。如果任一审批节点驳回交易，则该交易不会继续执行。

4. **签名**

审批通过后，交易进入签名阶段。有签名权限的成员可以对交易进行签名。具体需要由哪些成员参与签名，取决于触发的策略或钱包的签名规则。当交易满足签名条件后，Cregis 将提交交易进行广播上链。

* **单签**：由策略指定的任意一位成员完成签名后，交易即可继续执行。
* **多签**：由策略指定的成员参与签名，签名人数达到钱包设置的签名门限后，交易方可继续执行。

5. **广播上链**

交易完成签名后广播上链，最终交易结果以链上执行结果为准。

## **协作中的角色**

在团队协作中，不同成员可以承担不同职责。

| 角色   | 主要职责                  |
| ---- | --------------------- |
| 发起人  | 发起交易申请                |
| 审批人  | 审核交易是否符合业务要求，并批准或拒绝交易 |
| 签名人  | 对交易进行签名，授权交易广播上链      |
| 查看人员 | 查看协作申请及交易处理情况         |
